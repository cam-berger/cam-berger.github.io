01 · Embedded

AI-Firmware

Provide an agent with the firmware for a device it has never seen. Reverse-engineer what that device does and write a standard, reusable interface for downstream tasks.

Years
2026 · Draper Laboratory
My role
Lead investigator and engineer
Status
Working on its test devices and its first real firmware, October 2026.

The problem

Most hardware runs handwritten firmware with no clear standard interface. When a system has a configuration change, someone must integrate it by hand.

What I built

A toolkit that pulls the flash from a microcontroller and hands the binary to an agent. The agent reads the code, tests what each function does on the running device, and writes a standard interface for the device. Capable of running offline on the edge.

At Draper, I am pointing it at the bio lab: the sensors and equipment that run PREDICT96, Draper’s organ-on-chip platform for testing drugs on human tissue, allowing us to build and run agentically controlled experiments through the driver.

How it works

  1. 1

    Read

    Pull the flash from the device. The agent gets only the binary: no source, no documentation.

  2. 2

    Probe

    It guesses what each function does and tests the guess on the running device.

  3. 3

    Standardize

    It writes an interface any AI or person can use.

Result

On its test devices and on its first real firmware, every run ended with a working driver that a fresh agent could pick up and use.

The real one is a Modbus server from the Zephyr RTOS, the kind of protocol industrial equipment talks in, run with its application code unchanged. All three runs passed every one of 315 checks. Across the five test setups, all 15 fresh runs passed, including a parameter store that used to trip over two-line error replies (891 of 891 checks). Six more real firmware projects are lined up but can’t run yet, and nothing has touched physical hardware so far.

What’s next

The next step is the one I want to take at the Media Lab: an agent that walks into an environment, learns every device in it, and represents the space as something a person can understand and act in. CRESt, from Ju Li’s lab at MIT, showed what an AI can do with lab equipment people integrated for it. I want to know whether an AI can integrate and interpret the equipment itself.

Why it matters

This is a way for an environmental network to assemble itself: an agent that learns each new sensor on its own, merging the physical “nervous system” of sensors with the efficient processing of ML and the analytical reasoning of modern AI.

Tools

Python, with Java for Ghidra scripts. Agents run in the OpenAI Codex CLI and reach the toolkit over MCP. Ghidra (headless decompilation), Renode (emulated STM32 devices), Zephyr’s native simulator, the Arm GNU toolchain, and esptool. pyserial, pyusb, and pyftdi over UART, I²C, SPI, USB, and TCP.

Disclosure

The general tool is public under the Generative Driver (Apache-2.0). Its Draper use is described only at a high level, pending release: no Draper code, data, or device specifics.
